# dsda-doom for PS Vita

A port of the [dsda-doom](https://github.com/kraflab/dsda-doom) source port to the
PlayStation Vita (HENkaku/Ensō), with a WAD launcher.

## Installing

1. Install `dsda-doom.vpk` with VitaShell.
2. Copy your WADs to `ux0:data/dsda-doom/wads/`
   - IWADs: `doom.wad`, `doom2.wad`, `tnt.wad`, `plutonia.wad`, `freedoom1.wad`,
     `freedoom2.wad`, `heretic.wad`, `hexen.wad`, ...
   - PWADs: `.wad`, `.zip`, `.pk3`
   - Patches: `.deh`, `.bex`
3. Start dsda-doom from the LiveArea.

IWADs are detected by their header, so the file name does not matter.

## Launcher

| Step | What happens |
|------|--------------|
| 1. IWAD | Pick one IWAD (Cross) |
| 2. PWADs | Toggle PWADs with Cross. The number is the load order; Square moves the highlighted file one place earlier. |
| 3. DEH/BEX | Same as PWADs, for DeHackEd patches |
| 4. Start | Summary, start the game, clear the selection or rescan the folder |

Triangle goes to the next step, Circle goes back, START launches from any step.
The last selection is remembered (`ux0:data/dsda-doom/launcher.cfg`), so after the
first time the launcher opens on the Start page.

Extra command-line arguments (for example `-complevel 9` or `-warp 1 -skill 4`)
can be put in `ux0:data/dsda-doom/extra_args.txt`, one argument per line.
Lines starting with `#` are ignored.

## Default controls

| Button | Action |
|--------|--------|
| Left stick | Move / strafe |
| Right stick | Turn / look |
| R | Fire |
| L | Run (hold) |
| Cross | Use |
| Triangle / Square | Next / previous weapon |
| Select | Automap |
| Start | Menu |
| D-pad up / down | Fly up / down (Heretic, Hexen) |

Everything can be rebound in the in-game options menu.

## Notes

- Renderer: software only. The OpenGL renderer is compiled against no-op stubs
  and cannot be selected. The default resolution is 426x200 (16:9 at vanilla
  height); higher resolutions can be chosen in the options menu but cost
  frame rate.
- Config, saves, demos and screenshots are stored in `ux0:data/dsda-doom/`.
- Video capture (`-viddump`) is not supported.

## Building

Install [VitaSDK](https://vitasdk.org), then:

```sh
prboom2/vita/build.sh --deps    # --deps installs the required vdpm packages
```

The VPK is written to `prboom2/build-vita/src/dsda-doom.vpk`.
The GitHub Actions workflow `.github/workflows/vita.yml` does the same and
uploads the VPK as a build artifact.

### How the port is put together

| Path | Purpose |
|------|---------|
| `cmake/DsdaVitaDependencies.cmake` | Static VitaSDK libraries in link order |
| `src/vita/gl_stubs.c` | No-op GL entry points (generated by `tools/gen_gl_stubs.py`) |
| `src/vita/glu_stub.*` | No-op GLU tessellator |
| `src/SDL/i_system.c` | `ux0:data/dsda-doom` as config/data directory |
| `src/SDL/i_main.c` | Heap size, CPU clocks, reading `launch_args.txt` |
| `src/SDL/i_video.c` | Forces the software renderer |
| `src/dsda/configuration.c`, `src/m_misc.c` | Vita defaults and pad bindings |
| `src/i_capture.c` | Video capture disabled (no child processes) |
| `vita/launcher/launcher.c` | vita2d launcher (`eboot.bin`) |
| `vita/sce_sys/` | LiveArea assets (`tools/make_livearea.py`) |

The launcher writes the command line to `ux0:data/dsda-doom/launch_args.txt`
(one argument per line) and starts `app0:dsda-doom.bin`, which reads that file
when it gets no command-line arguments of its own.
